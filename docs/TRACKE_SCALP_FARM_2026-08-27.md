# Track E — 단타 팜 (Scalp Farm) 사전등록 명세 (2026-08-27)

> 명세 v1, Codex 1라운드 반영 확정본. 본 문서가 사전등록 원본이며 T0 이후 수치·규칙 변경 금지.
> 변경이 필요하면 신규 트랙을 별도 사전등록한다.

## TL;DR
**페이퍼 전용 10셀(5전략 × 2바스켓) 단타 팜.** 알파 탐색이 아니라 (a) 사용자 가시 단타
실험, (b) 실행 파이프라인 검증·비용 침식 관찰, (c) 상관된 다중 경로에서 승자가 자연
발생하는 현상(사후선택 함정)의 라이브 시연이 목적이다. **어떤 셀도 실거래·승급 후보로
선발 금지.** 판정은 사전 지정 3시점(T+30/90/180)의 공동 null 부트스트랩뿐이다.

## 1. 지위 (동결)
- **페이퍼 전용. 실주문·실자금 0. 승급 근거 사용 영구 금지** (Track B 방화벽 전례).
- 목적: (a) 사용자 가시 단타 실험 (b) 실행 파이프라인 검증·비용 침식 관찰
  (c) 상관된 다중 경로에서 승자가 자연 발생하는 현상(사후선택 함정)의 라이브 시연.
- 알파 탐색 아님. Track E 성과로 어떤 셀도 실거래·승급 후보로 선발 금지 —
  후보를 살리려면 별도 트랙을 신규 사전등록해 새 전방 데이터로 재검증.
- 명칭: "지갑" 금지 (H2 실제 지갑과 혼동) → **가상계정/셀 E01~E10**.

## 3. 실행 교정 (성과 조회 전 전 셀 일괄 — Codex 지적 인과성 결함 수정)
1. BRK: 스탑·수량 산정에 **ATR[i−1]** (같은 봉 완성 ATR 사용 금지).
2. ATR의 TR은 **previous close** 기준 (swing.py 버그 재발 금지).
3. MR·RSI-DIV: 신호는 확정봉 종가로 계산, **체결은 다음 봉 시가** (신호봉 종가 체결 금지).
   BRK 돌파는 봉내 스탑주문 모델(터틀 전례: 돌파 레벨 체결 + 갭 악화) 유지.
4. 4h 봉: UTC [00,04,08,…) 정렬, 닫힌 1h봉 4개 전부 있을 때만 확정.
5. 누락 봉 구간 fail-closed(해당 셀 그 봉 무행동 + 경고 로깅). 보간 금지.
6. 워밍업(지표 초기화)은 T0 이전 봉으로만, **T0 이전 주문 생성 금지** (과거 재생 거래 금지).
7. 펀딩: 실제 정산 시각(00/08/16 UTC)별로 그 시점 보유 포지션에 적용.
8. 이벤트 유일키 (cell, symbol, strategy, bar_close, action) — 재실행 멱등.
9. 상태·원장 원자적 체크포인트 (임시파일→rename, 상태와 이력 동일 트랜잭션 순서).

## 9. RSI-DIV 이식 대조 체크리스트 (lab/rsi_divergence_test.py → scalp_farm.py)

아래는 **원본 규칙 자체가 정확히 옮겨졌는지** 엔진 코드와 1:1 대조할 항목이다.
원본과 의도적으로 다른 항목은 #1·#11(교정)과 #13·#17(교정 파생 — 아래 '확정 사항'에서
결정 완료)이며, #15는 원본 유지로 확정, 나머지는 원본과 완전 일치해야 한다.

`append_csv_atomic` 은 append 마다 파일 전체를 `pd.read_csv` → `to_csv` 로 재작성했다.
pandas 의 기본 `float_precision='high'`(precise_xstrtod)는 correctly-rounded 가 아니라
`to_csv` 가 쓴 최단 표기를 되읽을 때 ±1 ULP 어긋난다. 어긋나는 방향은 플랫폼·pandas
구현에 의존한다(원인을 FMA 등으로 단정하지 않는다 — 어셈블리 증거 없음).

결과는 두 가지다.
1. **기존 행 변조.** 커밋된 라이브 파일에서 유일키가 같은 기존 행이 실제로 바뀌었다:
   `logs/tracke_ledger.csv` **71건**, `logs/tracke_variant_ledger.csv` **42건**
   (예: E01/BTC/1787821200000/enter 의 qty `0.06690434152495012` → `0.0669043415249501`).
   이는 `keep="first"` 가 문서로 약속한 "재실행이 기존 이벤트를 덮지 못한다"의 위반이다.
   (드리프트는 매시 누적이 아니라 **각 행이 최초로 재작성될 때 1회 이동한 뒤 고정점**이다.)
2. **그룹 간 결합.** 한 실행에서 통합 변형 원장(VLEDGER)에 append 되는 횟수는
   `1 + (v2 활성) + (v3 활성)` 이다. 즉 E11 행이 겪는 재작성 횟수가 변형 그룹 활성
   여부에 따라 달라져, §10~§12 의 단계별 바이트 격리 보증이 저장 경로에서 깨졌다.
   (`1 + v2 + v3` 은 각 저장 단계까지 정상 도달한 실행에 한한다 — 초기화·중간 실패 실행은
   다르다.) 이번 차이는 **CSV 재작성 경로만으로 전부 재현됐고 계산 경로 차이는 관찰되지
   않았다** — 셀 로직·체결·사이징에서 결함은 발견되지 않았다.

### 수정 (실행 코드는 carrybot/aggressive/scalp_farm_runner.py 만 — 그 외 테스트·본 문서)
- `append_csv_atomic` / `_migrate_vhist_schema` 가 기존 파일을 `dtype=str`
  (`keep_default_na=False, na_filter=False`)로 읽어 **필드 문자열을 수치형으로 재해석하지
  않고** 옮긴다. 신규 행은 같은 `to_csv` 직렬화를 거쳐 문자열 공간에서 유일키를 비교하므로
  중복 제거 의미(keep first/last)는 그대로다.
- 부수 효과로 dtype 승격 사고(기존 `"100"` 이 신규 실수 행 때문에 `"100.0"` 이 되는 것)도
  사라진다.
- **보장 범위 (과장 금지)**: 이건 raw-byte copy-on-write 가 아니다. 보장은 `to_csv` 가
  만든 정규형 CSV(LF 개행, 불필요한 인용 없음, 결측은 빈 필드)에 한정된다 — 손으로 넣은
  인용부호·CRLF·BOM 은 재작성에서 정규화된다. Track E 의 네 CSV 는 전부 이 경로가
  생성·관리하는 정규형이다. 또 신규 행 직렬화가 이제 단독으로 일어나므로, 이론상 예전의
  concat dtype 강제와 다른 표기가 나올 수 있다(현 스키마의 float/int 계약에서는 실측상
  동일). pandas `to_csv` 표기 규칙 변화까지 막지는 못한다.
- **전략 코드(`scalp_farm.py`)·판정기(`lab/tracke_null.py`)는 손대지 않았다.** 판정기는
  동결 파일이고, 원장 바이트가 더 이상 변하지 않게 된 이상 그 파서 오차는 주어진 파일에
  대해 결정적이다. 다만 판정은 **Linux x86-64 / Python 3.11 환경에서 수행**하고 그때의
  pandas·numpy 버전을 함께 기록한다. 부트스트랩 경계가 1 ULP 수준으로 근접하면 판정을
  보류·공시한다.
