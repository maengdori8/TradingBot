# TradingView 실전 후보 V3 검증 보고서

## 판정

**FAIL — 실거래 연결 금지, 페이퍼 연구만 허용.**

교정된 후보는 편도 8bp와 실제 펀딩률을 반영한 전체 과거자료에서 플러스였지만, 실전 스트레스와 통계 하한을 통과하지 못했다. 12bp에서 PF는 `1.124`, 5개 심볼 중 BTC·DOGE가 음수였고, 20·50거래 및 28일 달력 블록 부트스트랩 하한이 모두 음수였다. 이미 관측한 자료로 만든 후보라 진정한 사전등록 OOS도 아니다. 이 discovery 검증기는 코드상 PASS를 발급할 수 없다.

따라서 차트 스크립트는 의도적으로 `연구 FAIL·실거래 금지`를 표시한다. 수익 보장 문구나 고정 승률은 표시하지 않는다.

## 왜 원래 요청과 다른 후보도 만들었는가

영상 방식, ICT, Bollinger Band, RSI, MTF, FVG·OB·OTE, 거래량·매물대 등 여러 근거를 합친 최초 실행형 지표는 검증에서 탈락했다.

- 12,431거래
- PF `0.654`
- 기대값 `-0.106R`
- 9개 `심볼 × 시간봉` 셀 중 전체 양수 `3개`, 홀드아웃 양수 `2개`

지표 수를 늘리는 것은 독립적인 정보가 늘어나는 것과 같지 않다. 서로 강하게 상관된 기술지표를 점수로 더하자 1분·5분 노이즈와 비용만 늘었다. 이 결과는 [`TRADINGVIEW_EXECUTION_OVERLAY_VALIDATION.md`](./TRADINGVIEW_EXECUTION_OVERLAY_VALIDATION.md)에 보존했다.

V3는 그 실패 뒤에 억지로 ICT·Bollinger 조건을 더하지 않고, 장기 자료에서 상대적으로 덜 나빴던 `1시간 확정 종가 돌파 + SMA200 + RSI14 + 거래량`만 남긴 반증용 후보다. 하위 1·5·15분 차트는 실행 화면이고, 신호 판단은 확정 1시간봉만 쓴다.

## 실행 계약

- 방향: 롱만 거래. 하락 돌파는 신규 숏이 아니라 롱 리스크오프다.
- 진입: 현재 1시간봉 종가가 그 봉을 제외한 이전 24시간 고가를 돌파하고, 한 봉 전 SMA200·RSI14·거래량 게이트가 모두 통과한 뒤 다음 봉에 실행한다.
- 최후 손절: 신호 시점 확정 ATR24의 6배. 진입 뒤 절대 멀어지지 않는다.
- 채널 청산: 이전 12시간 저가와 최후 손절 중 높은 값을 사용하고, 한 번 올라간 값은 다시 내리지 않는다.
- 보유: 24시간에 추세를 한 번 재심사하고, 통과하면 최대 72시간까지 둔다.
- 위험: 설정당 `0.25%`; 최초 `80%`, 조건부 추매 1~4 각각 `5%`.
- 추매: 최후 손절거리의 20%·40%·60%·80% 구간을 터치한 뒤 상승 재확인. 과거 가격으로 소급 체결하지 않는다.
- Pine 전용 연패 제어: 설정 단위 2연패부터 위험 절반, 4연패부터 1/4.
- Pine 전용 회로차단: 단일 차트 명목가/자본 100%, 일 손실 1.5%, 전략 낙폭 10% 정지.
- 비용: 편도 8·10·12bp, 실제 Bybit USDT 무기한 펀딩률, 정산시각 1시간봉 시가 가격 프록시를 재생한다.

고정 TP는 없다. `채널 추적 청산`이 이익 보호와 추세 종료를 담당한다. 이를 고정 익절가처럼 부르면 안 된다.

## 독립 감사에서 잡아 수정한 결함

- Pine 돌파 채널이 신호봉 자체 고가·저가를 포함해 진입이 수학적으로 0건이던 오프셋을 수정했다.
- Pine `calc_on_order_fills`의 동일 봉 재초기화 가능성을 제거하고 명시적 pending/active 상태를 사용했다.
- Pine 주문 JSON에 고유 event/order ID, limit, 만료시각, stop revision을 넣고 미체결·설정종료 취소 알림과 `cancel_all`을 추가했다.
- TradingView 내장 위험강제청산 대신 JSON 체결 메시지가 있는 일손실·총낙폭 회로차단을 직접 구현했다.
- 추매 확인봉 가격으로 소급 체결하던 낙관 체결을 제거했다.
- 추매 다음 시가와 같은 봉의 손절을 누락하던 순서를 수정했다.
- 추매 수량을 실제 체결가와 최후 손절 간 거리로 다시 계산하도록 검증기를 수정했다.
- 진입 봉부터 손절·채널 청산을 검사한다.
- 무추매 비교군을 최초 80%가 아니라 동일한 100% 위험으로 맞췄다.
- 심볼별 덩어리 순서 MDD를 버리고 청산시각순 실현 MDD를 사용한다.
- `0.25%` 하드코딩을 제거하고 설정 위험률을 사용한다.
- 끝 자료도 같은 확률로 뽑는 순환 거래 블록과, 같은 날짜의 모든 종목 손익을 묶은 순환 28일 달력 블록 부트스트랩을 추가했다.
- 펀딩 열·중간 정산·앞뒤 커버리지가 없으면 검증을 중단한다.
- 24시간 심사는 한 번만 수행하고 72시간 청산을 별도 라벨로 기록한다.

이 계약은 11개의 합성 회귀 테스트로 고정했다. 여기에는 4단계 추매 전부의 순차 체결·총 위험 1R, 데이터 끝 미완결 거래 제외, 표준 JSON `null`, 순환 부트스트랩 전체 시작점 사용이 포함된다.

## 추매 반증

| 구조 | PF 8bp | 기대값 | 순손익 | 실현 MDD | 0.25% 환산 MDD |
|---|---:|---:|---:|---:|---:|
| 조건부 4회 허용 | 1.200 | +0.0372R | +62.08R | 19.77R | 4.94% |
| 무추매·항상 100% 위험 | 1.205 | +0.0470R | +78.36R | 24.24R | 6.06% |

원단위 낙폭 감소의 대부분은 추매 후보가 거래당 평균 `0.809R`만 투입한 결과다. 실제 투입 위험으로 나누면 후보의 기대값/PF/실현 MDD는 `+0.0483R / 1.211 / 23.84R`, 무추매는 `+0.0470R / 1.205 / 24.24R`로 후보가 아주 조금 높지만 통계적으로 검증되지 않았다. 추매1은 293건(17.57%), 추매2는 16건(0.96%), 추매3·4는 0건이다. 따라서 3·4차 추매는 구현됐을 뿐 역사적으로 검증된 규칙이 아니다.

현재 증거로는 추매의 독립 개선 여부가 미확정이다. 단계별 최소 30건을 요구하는 게이트에서 추매2·3·4가 실패했다. 향후 전방 자료에서 무추매보다 개선하지 못하면 제거해야 한다.

## Pine과 Python의 남은 차이

Python은 1시간 신호 다음 1시간봉 시가를 재생한다. Pine은 1·5·15분 차트에서 확정 1시간 정보가 공개된 뒤 첫 하위봉에서 신호 종가 제한 주문을 내며, 위쪽 갭이면 추격하지 않는다. Pine의 하락 24시간 돌파 백업청산, 2·4연패 위험감산, 명목가 한도, 일손실·총낙폭 회로차단, 계약 수량 절삭도 Python 성과에는 없다. 실제 체결 지연·미체결·봉내 경로까지 달라 둘은 동일 전략 백테스트가 아니다. Python PF를 현재 Pine 성과로 해석하거나 Strategy Tester에 고정 표시하지 않는다.

Pine의 시장·지정 주문 알림은 거래소 네이티브 보호주문이 아니다. 자동 실행기를 붙인다면 최초 체결 즉시 거래소에 reduce-only stop-market을 등록하고, 추매 체결 시 수량만 갱신해야 한다. TradingView·웹훅 장애 동안 거래소 보호주문이 없다면 실전 구조가 아니다.

2026-08-31 TradingView의 Bybit BTCUSDT.P 차트에서 실제 Pine v6 컴파일과 런타임을 확인했다. 1분·5분·15분 모두 컴파일·런타임 오류는 0이었다. 화면에 로드된 2026-07-01~08-31의 작은 표본은 각각 `2/4/12`거래에 불과했고 PF는 `0.285/1.285/0.748`이었다. 5분의 4거래 PF 1.285는 표본 부족으로 성과 근거가 아니며, 1분·15분은 이 짧은 구간에서도 음수였다.

## 통과 조건

- 결과를 보기 전에 코드·파라미터·유니버스·데이터 cutoff를 커밋과 SHA256으로 사전등록
- 완전히 새로운 미래 자료에서 최소 200~300건 페이퍼 체결
- 편도 12bp와 실제 펀딩 후 PF 1.20 이상
- 20·50거래 및 동기화 달력 블록 p05 모두 0 초과
- 전 종목과 최소 4개 완전연도 양수
- 시간순 MTM 포트폴리오, 동시 heat, 마진, 갭, 지연, 부분체결, 주문거절 스트레스 통과
- 각 추매 단계 최소 30건과 동일 투입위험 무추매 대비 위험효율 개선
