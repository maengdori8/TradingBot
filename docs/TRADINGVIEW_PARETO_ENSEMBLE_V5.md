# Pareto Ensemble V5 검증 및 TradingView 사용 계약

## 판정

**FAIL — 연구·페이퍼 전용, 실거래 승격 금지.**

V5는 기존 24/12 돌파 기준보다 과거자료의 비용 후 수익효율과 실현 낙폭이 좋아졌고,
작은 probe를 포함한 원신호도 늘었다. 그러나 더 엄격하게 다시 계산하면 다음 세 조건을
통과하지 못했다.

- 추가 신호 707개는 설정 위험의 `0.05R`만 쓰는 probe다. 이를 1R 거래와 똑같이 세면
  빈도가 부풀기 때문에 위험등가 월 중앙값을 주 지표로 바꿨고, 후보 `18.35` 대 기준
  `26.00`으로 실패했다.
- 후보-기준을 같은 달력 블록으로 뽑은 paired bootstrap에서 위험정규화 기대값과 실현
  낙폭 개선은 통과했지만, 절대 순R 차이 p05는 네 블록 모두 음수였다.
- 공통구간에 완전한 연도는 2023~2025 세 개뿐이며, 상위 수익 이벤트 5개를 제거하면
  PF가 `1.161`로 1.20 게이트를 실패했다.

따라서 이 버전을 “수익이 검증된 지표”라고 부르면 안 된다. 현재 증거가 허용하는 표현은
`수익효율·실현 낙폭 개선 가능성이 있는 고정 discovery 후보`까지다.

## 영상·ICT·Bollinger를 그대로 실행 규칙에 넣지 않은 이유

제공된 영상의 핵심은 Bollinger Band 이탈, Stochastic 교차, STC 반전을 겹치고 분할
진입으로 평단을 조절하는 구조다. 별도 구현에서 ICT(FVG·OB·OTE·유동성), Bollinger,
RSI, Stochastic, STC, MTF, 거래량·매물대를 함께 검증했지만 비용 후 결과가 무너졌다.

- 최초 ICT·Bollinger MTF: 1·5·15분 9개 셀에서 편도 8bp 후 모두 음의 기대값
- 실행형 합성 오버레이: 12,431거래, PF `0.654`, 기대값 `-0.106R`
- 영상식 반전 신호의 추가 확인 조건은 거래 수를 줄이거나 비용 민감도를 키웠고,
  장기 돌파 후보의 실행 게이트를 개선하지 못했다.

기술지표는 여전히 [`ict_bb_mtf_confluence.pine`](../tradingview/ict_bb_mtf_confluence.pine)에서
상황 설명용으로 볼 수 있다. 다만 V5 주문을 허가하거나 크기를 늘리는 근거로 쓰지 않는다.
검증에서 탈락한 조건을 보기 좋다는 이유로 실행 규칙에 되돌려 넣지 않았다.

## 고정 실행 구조

V5는 롱 전용 세 sleeve를 서로 독립 상태로 재생한다. Scout는 독립 알파가 아니라 작은
baseline probe다.

| sleeve | 설정 위험 | 진입 | 청산 |
|---|---:|---|---|
| CORE | 90% | 이전 24시간 고가 돌파 + q60 저변동 필터 | 12시간 저가 추적 |
| SCOUT | 5% | 같은 24시간 원돌파, q 준비구간만 | 12시간 저가 추적 |
| FAST | 5% | 이전 12시간 고가 돌파 + q60 저변동 필터 | 6시간 저가 추적 |

공통 규칙은 다음과 같다.

- 신호: 확정 1시간봉, SMA200·RSI14·거래량 게이트
- q 필터: 현재 후보를 제외한 `[t-365일, t)` raw 돌파의 상대 ATR, pandas와 같은
  linear 60분위, 최소 30표본과 365일 full-window
- 체결: 신호 다음 1시간봉 시가
- 최후 손절: 신호의 이전 확정 ATR24 × 7, 진입 뒤 절대 멀어지지 않음
- 보유: 24시간에 추세 한 번 재심사, 최대 72시간
- 비용: 편도 12bp + 실제 Bybit 펀딩; severe는 편도 20bp + 펀딩 차변 2배·대변 0
- 설정당 가격위험: `0.25%`; 5종목 동시 상한 `5R = 1.25%`
- 추매·숏: 비활성화

추매 1~4는 사용자의 요청대로 이전 버전에 구현했지만 표본이 `293/16/0/0`에 그쳤고,
동일 위험 무추매보다 검증된 개선이 아니었다. 특히 3·4차는 역사 표본이 0건이라 V5에서
켜지지 않는다. 무제한 물타기나 손절 확대는 허용하지 않는다.

## 엄격 재검증 결과

Bybit BTC·ETH·SOL·XRP·DOGE 1시간봉, 실제 펀딩 공통구간을 사용했다. q warm-up과
5심볼 공통 readiness 뒤인 `2022-10-23 09:00 UTC`부터 마지막 신호의 73시간 완전
follow-up을 확보한 `2026-08-21 02:00 UTC`까지 집계했다.

| 12bp + 실제 펀딩 | V5 | 동일 coverage 24/12 기준 |
|---|---:|---:|
| 엔진 구성 거래 | 3,191 | 1,232 |
| 고유 진입 이벤트 | 1,577 | 1,232 |
| 투입 위험 합계 | 888.85R | 1,232.00R |
| PF | 1.425 | 1.258 |
| 위험정규화 기대값 | +0.0894R | +0.0539R |
| 순손익 | +79.46R | +66.37R |
| 실현 MDD | 14.19R | 22.09R |
| 월 원신호 중앙값 | 33.00 | 26.00 |
| 월 위험등가 중앙값 | 18.35 | 26.00 |
| 월 위험등가 p10 | 9.71 | 13.00 |

원신호는 늘었지만 자본을 같은 크기로 더 자주 투입한 것은 아니다. 이벤트 위험 분포는
`1.00R 750건`, `0.95R 102건`, `0.90R 6건`, `0.10R 12건`, `0.05R 707건`이다.
따라서 “33회 대 26회”만 인용하지 말고 위험등가 빈도를 반드시 함께 제시해야 한다.

Severe 20bp에서는 V5 PF `1.210`, 기대값 `+0.0495R`, 순손익 `+43.99R`로 점추정은
양수였다. 그러나 14·28·56·84일 bootstrap의 순R p05는 모두 음수였다.

후보-기준 paired bootstrap 결과는 다음과 같다.

| 공통 달력 블록 | 절대 순R 차이 p05 | P(순R 우위) | 위험효율 차이 p05 | P(실현 MDD 개선) |
|---:|---:|---:|---:|---:|
| 14일 | -3.49R | 90.32% | +0.0112R | 97.32% |
| 28일 | -5.26R | 88.43% | +0.0112R | 98.11% |
| 56일 | -6.97R | 85.97% | +0.0110R | 97.96% |
| 84일 | -7.81R | 85.25% | +0.0112R | 97.90% |

즉 같은 위험을 덜 쓰면서 얻는 효율과 실현 낙폭은 개선됐지만, 절대 수익이 기준보다
높다는 95% 하한은 확보하지 못했다. 실현 MDD는 MTM·마진·강제청산을 포함하지 않는다.

## TradingView 두 파일 계약

- [`pareto_ensemble_v5_60m_strategy.pine`](../tradingview/pareto_ensemble_v5_60m_strategy.pine):
  표준 60분봉 전용. 확정봉 주문을 다음 1시간 시가에 체결하는 권위 전략이다.
- [`pareto_ensemble_v5_ltf_overlay.pine`](../tradingview/pareto_ensemble_v5_ltf_overlay.pine):
  표준 1·5·15분봉 전용. `[1] + lookahead_on` 확정 1시간 데이터만 사용하는 표시·관찰
  오버레이다. payload는 `execution_authority=false`이고 주문용이 아니다.

한 하위 시간봉 전략에서 non-repaint HTF 공식 패턴과 Python의 정확한 다음 1시간 시가
역사 체결을 동시에 보장할 수 없어서 두 파일로 분리했다. LTF 역사 마커는 첫 하위봉
종가에 계산될 수 있으므로 체결 증거로 사용하지 않는다.

### 직접 MCP 적용 및 컴파일 확인

`2026-08-31`에 로컬 TradingView Desktop의 loopback CDP/MCP 연결을 통해
`BYBIT:BTCUSDT.P` 차트에 직접 적용했다.

| 파일 | 차트 | Pine marker | 차트 런타임 |
|---|---|---:|---:|
| 권위 전략 | 표준 60분 | 오류 0, 경고 0 | 차트 업데이트 성공 |
| 표시 오버레이 | 표준 1분 | 오류 0, 경고 0 | 사용자 정의 오류 0 |
| 표시 오버레이 | 표준 5분 | 오류 0, 경고 0 | 사용자 정의 오류 0 |
| 표시 오버레이 | 표준 15분 | 오류 0, 경고 0 | 사용자 정의 오류 0 |

TradingView 개인 Pine 영역에도 다음 이름으로 각각 저장했다.

- `RESEARCH Pareto Ensemble V5 — 60m Authoritative`
- `Pareto Ensemble V5 — Confirmed 1H Overlay [1m/5m/15m]`

권위 전략은 실제 모의 체결가로 즉시 보호선을 설치하려고 `calc_on_order_fills=true`를
사용한다. TradingView Strategy Tester는 이런 전략에 예견 편향 가능성 경고를 표시할 수
있다. V5는 fill 재계산에서 신호·OHLC·q 배열을 전진시키지 않고 직전 확정봉 cache와 실제
모의 fill만 읽지만, 이 구현상 방어가 경고 자체를 증거로 뒤집지는 않는다. 따라서
TradingView Tester 수익표가 아니라 비용·펀딩을 포함한 Python 원장을 검증 권위로 둔다.

한 가지 미래 경계도 남는다. 최초 채널 보호선이 다음 시가 이상인 극단 갭에서는 Pine
broker emulator와 Python의 같은 봉 체결 순서를 완전히 같다고 보장하지 않는다. 동결된
3,191개 구성 거래에서는 해당 사례가 0건이었으므로 위 과거 수치는 바뀌지 않았지만,
전향 원장에서는 이 경우를 별도 기록하고 실제 거래소 체결 재생으로 판정해야 한다.

## 전향 검증 잠금

과거자료는 이미 반복 관측했으므로 PASS를 만들 수 없다. 파라미터·유니버스·비용·코드
해시를 잠그고 `2026-09-01` 이후의 새 자료만 누적한다.

- 최소 12개월이면서 최소 250 위험등가 진입
- 편도 12bp·실제 펀딩 후 PF ≥ 1.20, 위험정규화 기대값 > 0
- 5/5 심볼 양수, 확보 가능한 완전연도·롤링 연도 모두 양수
- 14·28·56·84일 자체 bootstrap p05 > 0, P(+) ≥ 95%
- paired 위험효율·절대 순R·실현 MDD 개선의 p05 > 0, P(+) ≥ 95%
- 상위 5개 이벤트 제거 후 PF ≥ 1.20, 기대값 > 0
- severe 20bp PF ≥ 1.05, 기대값 > 0
- 시간순 MTM, 최소 주문금액, 수량 절삭, 갭, 마진·강제청산, 주문지연·거절 포함

위 조건과 코드·데이터 해시는
[`config/pareto_v5_preregistration.json`](../config/pareto_v5_preregistration.json)에 고정했다.
전향 시작은 `2026-09-01 00:00 UTC`, 가장 이른 달력 판정은 `2027-09-01 00:00 UTC`이며,
그때도 250 위험등가 진입을 함께 채워야 한다. 신호나 PnL을 바꾸는 수정은 새 버전으로
분리하고 전향 시계와 표본 수를 0으로 되돌린다. 모든 게이트를 통과해도 실거래 자동
승격은 금지하며 별도 사용자 승인과 실제 체결·마진 재생이 필요하다.

동결 Pine SHA256은 다음과 같다.

- 60분 권위 전략: `0aec7adeb04fff4a8010f4cb7d34b79f01c21e260b8bacaf8b274178d54c02ea`
- 1·5·15분 오버레이: `b9886d3b65d9dfd3a4b2319872796f18d3bca7bc446bab9fffc4facdd7f16b4f`
