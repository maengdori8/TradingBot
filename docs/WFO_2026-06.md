# 워크포워드 검증 보고서 — 룩어헤드 정정 + 정직한 엣지 판정 (2026-06-13)

## TL;DR (정직한 결론)
**현재 ICT 컨플루언스 전략은 배포 가능한 엣지가 없다.** 2024-01 ~ 2026-06 (2.5년) × 14개 메이저
심볼 10,069 신호를 룩어헤드 없이 워크포워드 검증한 결과:
- 시장가(taker 0.21%) 실행: 모든 출구 조합 **음수** (최선 −0.112R), OOS −0.144R, 홀드아웃 −0.522R
- 지정가(maker 0.07%) 실행: 전체표본 최선 **−0.004R(겨우 손익분기)**, OOS −0.021R, 홀드아웃 −0.368R
- 그로스(비용 제외)는 미세하게 양수(+0.03~0.07R)지만 **거래비용이 전부 삼킨다**

**이전 연구(docs/RESEARCH_2026-06.md)의 +0.221R 등 '엣지'는 룩어헤드 버그의 산물이었다.** 정정 완료.

## 발견된 룩어헤드 버그 (치명적, 수정됨)
`research/study.py:replay_symbol`이 각 15m 결정 시점에 상위 타임프레임(1h/4h) 윈도우를
`searchsorted(ts, side="right")-1`로 선택 → **신호의 100%가 아직 닫히지 않은(형성 중) 4h·1h 봉을 사용**.
저장된 4h 봉은 최종 OHLC(예: 04:00 봉 = 04:00~08:00 전체)를 담으므로, 05:00 시점에 그걸 쓰면
**최대 4시간의 미래 가격**을 본다. ICT가 RR3.5에서 승률 32~42%로 비정상적으로 좋았던 원인.

### 수정
```python
# 결정 시각 = 15m 바 종가 시점. 그 시점에 '완전히 닫힌' HTF 봉만 사용
dec = ts15.values + np.timedelta64(15, "m")
idx1h = np.searchsorted(df1h.index.values, dec - np.timedelta64(1, "h"), side="right") - 1
idx4h = np.searchsorted(df4h.index.values, dec - np.timedelta64(4, "h"), side="right") - 1
```

## 4슬롯 포트폴리오 시뮬 (research/portfolio.py — 실거래 제약)
신호당 R이 아니라 max_positions=4 + 점수차등리스크 + 연패축소 + 손절 후 8h 쿨다운 +
1심볼 1포지션을 시간순 적용. **쿨다운은 청산(손실 실현) 시점에만 설정(룩어헤드 차단).**

| 설정 (메이커) | 전체 2.5년 자본 | MDD | 홀드아웃 60일 자본 |
|------|------|------|------|
| 라이브 RR2.5 + 오버레이 | ×0.98 | 37% | ×1.01 |
| WFO최선 m3_rr3.5 + 오버레이 | ×1.26 | 26% | ×0.96 |
| 라이브 RR2.5 + 오버레이 OFF | ×0.27 | 82% | — |

- WFO최선의 ×1.26은 **인샘플 파라미터 선택 + 2024-25 추세장**의 산물 → 홀드아웃에서 ×0.96으로 소멸
- **연패축소+쿨다운 오버레이의 가치 = 알파 창출(✗)이 아니라 자본 보존(✓)**: 라이브 설정 기준
  ×0.27→×0.98, MDD 82%→37%. 제로엣지 신호를 생존시킬 뿐.
