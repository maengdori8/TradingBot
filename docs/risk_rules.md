# 리스크 관리 규칙

> 기존 ICT는 페이퍼 벤치마크이며 실전 승급이 동결되어 있다. 단일 진실원천은
> `config/config.yaml`이고, 레거시 `promote` 점수만으로 실전 주문을 활성화할 수 없다.

## 1. 자본 배분 구조

```
전체 자산: 5,000 USDT
├── 트레이딩 자본 (25%): 1,250 USDT  ← 봇이 사용하는 금액
└── 보호 자본 (75%): 3,750 USDT      ← 절대 건드리지 않음
```

트레이딩 자본만 손실 위험에 노출. 최악의 경우에도 전체 자산의 25%만 손실.

## 2. 포지션 사이징 (컨플루언스 점수 차등)

리스크 금액 = 트레이딩 자본 × 점수별 risk_pct:

| 등급 | 점수 | risk_pct | 리스크 금액 |
|------|------|----------|------------|
| A | 85+ | 0.7% | 8.75 USDT |
| B | 75~84 | 0.5% | 6.25 USDT |
| C | 70~74 | 0.3% | 3.75 USDT |
| BTC 역추세 | 무관 | 0.3% 강등 | 3.75 USDT |

```
포지션 수량 = 리스크 금액 / |진입가 - 손절가|
손절 = 2.0 × ATR(14) / 목표 = 손절거리 × 2.5  (최소 R:R = 1:2.5)
레버리지 = 자동(손절거리 기반, 최대 10x, 청산가는 항상 손절가 바깥)
```

> 위 값은 ICT 페이퍼 벤치마크용이다. 자동학습은 현재 `dry_run`으로 제안만 기록하며
> `logs/learned_params.yaml`을 실행 설정에 적용하지 않는다.

## 3. 서킷브레이커 조건

| 조건 | 한도 | 조치 |
|------|------|------|
| 일일 손실 | 트레이딩 자본의 5% (62.5 USDT) | 당일 거래 중단 |
| 주간 손실 | 트레이딩 자본의 12% (150 USDT) | 주간 거래 중단 |
| 연속 손실 | 7연패 | 1일 강제 휴식 |

> 7연패 기준: 신체제 설계 승률(~40%)에서 5연패는 확률 7.8%의 일상 변동.
> 7연패(2.8%)가 구설계의 "이상 신호" 희귀도와 동급.

서킷브레이커 상태는 SQLite(`logs/circuit_breaker.db`)에 영속화.
봇 재시작 후에도 차단 상태 유지.

## 4. 동시 포지션 관리

- **최대 동시 포지션: 4개** / 심볼당 1개
- 같은 방향 최대 3개 (한쪽 쏠림 방지)
- 총 담보금 < 트레이딩 자본의 80%

## 5. 레거시 성과 표시 기준

`config.yaml`의 `promote` 섹션은 대시보드 표시 호환용이다. 아래 조건을 만족해도
`promote.frozen: true`인 전략은 실전 전환할 수 없다.

| 지표 | 최소 기준 | 비고 |
|------|---------|------|
| 총 거래 횟수 | ≥ 50건 | 레거시 최소 표본 |
| 승률 | ≥ 38% | RR2.5 손익분기 28.6% + 마진 |
| Profit Factor | ≥ 1.5 | |
| MDD | ≤ 10% | 40% 승률의 연패 변동 반영 |
| 샤프지수 | ≥ 1.0 | |
| 총 수익률 | ≥ 0% | 손실 상태 전환 불가 |

실제 승급은 오프라인 통계 게이트와 90일 이상 미래 데모 검증을 별도로 통과해야 한다.

## 6. 실전 파일럿 한도

- 최초 자본: 100만원과 투자 가능 자산 5% 중 작은 값
- 거래당 손절 위험 0.1%, 동시 총 손절 위험 0.5%, 최대 레버리지 2배·격리마진
- 일 손실 0.5%, 주 손실 1.5%, 고점 대비 낙폭 3%에서 신규 주문 중단
- 데이터 지연, 주문 오류, 포지션 대사 불일치는 손익과 무관하게 fail-closed
- 파라미터는 실시간 자동 변경하지 않으며, 새 버전은 전체 WFO·데모 게이트를 다시 통과
