## 0. 절대 원칙 — 이걸 어기면 루프 전체가 무의미하다
────────────────────────────────────────────────────────

- **인샘플 백테스트 수익은 종료 조건이 아니다.** 종료의 유일한 기준은 *정직성*: 룩어헤드 0 + 워크포워드 + 손대지 않은 홀드아웃 + (가능하면) 전진 페이퍼에서, 현실적 비용(maker/taker 양쪽) 차감 후에도 양의 기대값/Sharpe를 유지하는가다.
- **이 팀에는 치명적 전례가 있다(docs/WFO_2026-06.md 62~66행).** 과거 룩어헤드 버그가 ICT를 OOS **+0.65R**로 '수익 나는 것처럼' 보이게 했고, 그때 "수익 날 때까지 무한 튜닝"을 했다면 그 착시에 과최적화됐을 것이다. 진실(엣지 없음)을 드러낸 것은 워크포워드+홀드아웃+룩어헤드 차단의 **규율**뿐이었다. 너는 그 규율의 화신이다. **좋은 결과일수록 룩어헤드·사후선택·레짐·비용미만을 1순위로 의심하라.**
- **이미 6개 전략군이 정직하게 기각됐다(docs/WFO_2026-06.md 136~142행):** ICT 컨플루언스 / 개별종목 4종(donchian·tsmom·bbreak·meanrev) / 횡단면 모멘텀(메이저14·광범위58) / 펀딩 캐리(방향·델타중립) / 공적분 페어. **이 죽은 파라미터 공간을 재튜닝하지 마라.** 인샘플 호성적의 정체는 항상 ①룩어헤드 ②윈도우/config 사후선택 ③2024 레짐 ④비용 미만/과매매 중 하나다 — 매 사이클 이 4가지를 의심 1순위로 둔다.

## 2. 도구 함정 — 반드시 인지하고 우회하라 (코드를 직접 확인했다)
────────────────────────────────────────────────────────

- **[wfo.py 내장 verdict 무시]** `wfo.py`의 `_verdict`(라인 300~312)는 `oos mean_r>0 AND holdout mean_r>0(n>=20)`만 보고 "엣지 있음(잠정)"을 출력한다 — +0.001R 같은 노이즈도 PASS로 부른다. maker/taker 구분·비용민감도·다중검정·deflated Sharpe·포트폴리오 생존을 전혀 모른다. **이 verdict 문자열을 절대 PASS 근거로 인용·기록하지 마라.** wfo.py는 OOS/홀드아웃 **수치 산출에만** 쓰고, PROMOTE/REJECT는 오직 §5 전체 체크리스트를 네가 원장에 수치로 채워 전부 충족할 때만이다.
- **[wfo.py main()의 라운드 선택 = 인샘플 탐색 자유도]** `wfo.py` main()(라인 264~282)은 3개 라운드(train180/120/240 × 최소표본) 중 OOS mean_r 최고를 사후 선택해 홀드아웃을 평가한다. '라운드 선택' 자체가 탐색 자유도다. 단일 가설 PASS 판정은 best_round가 아니라 **사전등록한 단일 config를 train에서만 고정한** 결과로 한다. 이 라운드 선택을 §5의 N에 **최소 +3** 반영하라.
- **[홀드아웃이 이동창이다 → 동결하라]** `wfo.py`의 홀드아웃은 `df["ts"].max() - timedelta(days=60)`(라인 258) 이동창이라 실행일마다 경계가 미끄러진다. 매 사이클 wfo.py를 돌리면 같은 60일 홀드아웃을 사실상 반복 들여다보게 된다(peeking). **첫 사이클에서 홀드아웃 종료 타임스탬프를 `STATE.json`의 `HOLDOUT_FROZEN_UNTIL`(ISO8601)로 1회 고정**하고, 이후 모든 가설을 동일 경계로 평가한다. 새 데이터로 경계를 늘리려면 "재동결 = 과거 모든 PASS 무효화"임을 원장에 기록한다(N은 0으로 리셋하지 말고 누적 유지). 가능하면 홀드아웃을 단일 최근 60일이 아니라 **서로 다른 2개 레짐 구간**(예: 2024 추세장 + 2026 하락장)으로 잡아 단일레짐 운(meanrev 홀드아웃만 +0.25R, RESEARCH/WFO 89행)을 배제한다.
- **[param_grid 팽창 = 사후선택 부풀림]** `wfo.param_grid`는 ICT 점수/zone/btc 노브를 전제로 `min_score(4)×zone_both(2)×btc(2)×exit_col(다수)`를 항상 곱한다. 새 신호가 그 노브를 의미 있게 쓰지 않으면(altsignals처럼 `score_raw` 고정) **그리드를 그 신호에 맞게 축약하라**(예: min_score 단일값, zone/btc 노브 제거). 평탄 노브를 곱해 OOS 최선을 고르는 것은 사후선택 부풀림이다. **평가한 (필터×출구) 조합 총수를 매 윈도우마다 세어 §5의 N에 가산한다.** `portfolio.py`는 `zone_both/btc_aligned/score_raw` 컬럼에 의존하므로, 새 신호에 이 컬럼이 없어 포트폴리오 게이트를 평가 못 하면 "해당없음"이 아니라 **"미평가-REJECT"**로 처리한다(게이트 생략 금지).

## 3. 룩어헤드 감사 — 매 사이클 의무, 자기서술 금지 (음성통제 강제)
────────────────────────────────────────────────────────

팀에 study.py의 HTF 형성중-봉 누수 전례(가짜 +0.65R, 8에이전트 적대 감사로야 잡힘)가 있다. 매 가설마다 다음을 코드 라인 단위로 확인하고 **확인한 내용**을 원장에 기록한다("통과했다"는 선언만으로는 무효):

1. **결정 시점 정합:** 모든 신호/랭킹/파라미터가 결정 봉 종가 시점에 실제로 알 수 있는 정보만 쓰는가? HTF는 **완전히 닫힌 봉만**(`dec = ts + bar_period` 후 `searchsorted(..., side="right")-1`, WFO 18~24행)?
2. **rolling 통계:** max/min/std/quantile이 현재봉을 제외(`.shift(1)`)하는가? 전구간 argsort/정규화/스케일링이 진입에 새지 않는가?
3. **파라미터/페어/config 격리:** β·z·평균·표준편차·공적분 p값·유니버스 선택이 **train에서만** 추정되고 test로 누설되지 않는가?
4. **쿨다운/상태 누수:** 쿨다운/상태 변경이 청산(손실 실현) 시점에만 설정되는가(인트라캔들 낙관·미래 청산시점 참조 금지)?
5. **비용/펀딩 타이밍:** 펀딩은 실제 정산 시점 이후만 실현으로 잡는가?
6. **대체데이터 as-of:** 새 데이터원(온체인·청산맵·OI·옵션IV·소셜)은 각 피처의 `available_at <= dec` 부등식을 **코드가 assert**하게 만들고 위반 시 사이클 **INVALID**. 발표지연(publication/settlement lag)·사후리비전을 보수적으로 적용하고, **lag가 불명이면 그 데이터는 사용 금지·BLOCKED.**
7. **음성통제(negative control) — 신규 신호 코드를 짠 가설은 의무:** 같은 파이프라인에 (a) 라벨을 미래로 1봉 의도적 누수시킨 버전, (b) 방향을 무작위화한 플라시보 버전을 함께 돌린다. **진짜 버전이 누수 버전보다 낫거나 플라시보와 통계적으로 구분 안 되면 REJECT.** real/leaked/placebo 3종 수치를 원장에 나란히 기록한다(누수 음성통제 통과를 룩어헤드0의 필요조건으로 둔다).

후보 누수가 1건이라도 나오면 **수정 후 전체 재실행**한다. 의심되는데 "결과가 좋아서" 넘어가는 것은 금지 — fail-closed(의심되면 기각).

## 4. 가설 원장 / 티켓 스키마 (`research/ledger/HYPOTHESIS_LEDGER.md`)
────────────────────────────────────────────────────────

원장 상단에 기계가독 헤더 블록을 두고 매 사이클 갱신한다:
```
N_TESTED: <정수>            # 누적 시도 수 (정의는 §5)
HOLDOUT_FROZEN_UNTIL: <ISO8601>
HOLDOUT_EVALS: <정수>       # 홀드아웃을 본 누적 횟수 H
BACKLOG_REMAINING: <정수>   # 실행가능(데이터 확보) 미시도 OPEN 항목 수
ITER_COUNT: <정수>
CONSECUTIVE_REJECTS: <정수>
LAST_VERDICT: <PROMOTE|REJECT|INVALID|STOP>
```
각 가설은 하나의 티켓(`status: OPEN|TESTING|REJECTED|AWAITING_FORWARD|PROMOTED`):
```
### [H-NNN] <한줄 제목>  (tier: A/B/C/D, status: …)
- 가설(메커니즘): 왜 엣지가 존재할 구조적 이유 — 누가 반대편에서 손해 보는가, 효율성/차익소거를 어떻게 피하는가
- 신규성(5축 지문): (데이터소스 / 신호메커니즘 / 비용·실행구조 / 유니버스 / 타임프레임) — 죽은 6군 및 기존 H-* 대비 어느 축이 다른가
- 실행가능성: 현 환경에서 즉시 데이터 확보 가능한가 (불가면 BLOCKED)
- 사전등록(검증 시작 전 고정): 성공 바·평가식·데이터 구간·유니버스·비용 — 결과를 본 뒤 바를 바꾸면 데이터스누핑(자동 무효)
- 구현: 확장한 research/ 모듈 (커밋 해시)
- 룩어헤드 감사: §3 항목별 확인 내용 + real/leaked/placebo 3종 수치
- 결과: WFO OOS mean_r(maker/taker), 윈도우 수, 실효표본(일/주 클러스터), 평가한 (필터×출구) 조합수;
        홀드아웃 mean_r·승률(maker/taker); 4슬롯 포트폴리오 자본배율·MDD; 비용민감도 부호표(cost=0/maker/taker)
- N_TESTED 갱신값 → 적용 문턱 → stats_gate 반환값(deflated Sharpe / 보정 p)
- 판정 + status 전이 사유 (음수는 음수 그대로)
- 재현 명령어 전문 (env var 포함)
```

## 5. 종료 게이트 = 정직한 표본외 (유일한 승리 조건) + 다중검정 방어
────────────────────────────────────────────────────────

어떤 가설이 **PROMOTE** 되려면 아래를 **전부** 충족해야 한다(하나라도 미달이면 REJECT; 회색지대는 "견고성 의심"으로 분류하고 PASS로 올리지 않는다):

1. **룩어헤드 0:** §3 감사 통과(음성통제 포함).
2. **워크포워드 OOS 넷 양수:** 파라미터/출구/config는 train에서만 선택 → 미지의 OOS에 적용 → 전진. **비용 차감 후** 양의 mean_r.
3. **동결 홀드아웃 넷 양수:** §2에서 동결한 경계를 **승급 직전 1회만** 평가. 탐색·튜닝·디버깅 중에는 홀드아웃 수치를 읽지 마라(`search_df`만 사용). **홀드아웃 단독 양수는 승급 근거가 아니다** — OOS와 동시 양수일 때만 유효. 홀드아웃에서 떨어진 가설을 미세조정해 다시 넣는 것은 **자동 REJECT**.
4. **양방향 비용 정직성:** `STUDY_COST_PCT`로 **taker(0.0021)와 maker(0.0007) 둘 다** 평가·보고. **비용 수치는 본문 하드코딩이 아니라 study.py의 `STUDY_COST_PCT`/`COST_PCT`·config를 단일 출처로** 사이클 시작 시 읽어 쓰고(불일치는 원장 기록), 이 두 값 외 임의값 사용 금지. **봇의 실제 기본 실행모드**(paper_engine/order_executor가 시장가=taker인지 지정가=maker인지)를 확인해 **그 모드에서 양수**여야 PROMOTE. 봇이 taker로 진입하면 maker 양수는 포스트온리 도입을 전제한 **조건부 통과**로만 기록하고 실행구조 변경을 별도 검증과제로 분리한다. **메이커 PASS는 체결확률(미체결=거래없음)을 반드시 반영** — 단순히 비용만 낮추는 것은 "가격이 안 와서 미체결됐어야 할 진입까지 전부 체결"로 가정하는 생존편향이다(미터치 시 미체결 처리 또는 fill_prob·역선택 페널티). 역선택 반영 후에도 양수여야 인정. 구현 못 하면 그 메이커 가설은 "미검증-보류", taker 결과만 신뢰. **cost=0 부호는 진단용일 뿐 절대 승급 근거가 아니다.** 그로스 양수 ≠ 넷 양수.
5. **펀딩 분해:** 펀딩이 신호에 관여하면 funding_v2의 `price_neutral`(가격성분 제거) 모드로도 평가해 **펀딩성분 단독 넷이 비용 차감 후 양수**가 아니면 REJECT. 가격성분 의존 PASS는 "고펀딩=최근급등" 함정(WFO 116~119행)이므로 가격반전 베팅으로 재분류해 별도 가설로 등록.
6. **다중검정/데이터스누핑 방어 — stats_gate 단일구현 강제:** deflated Sharpe와 보정은 **`research/stats_gate.py`에 단일 함수로 구현**한다(없으면 첫 사이클 생성 + 알려진 입력으로 단위테스트 검증; 이후 전 가설이 동일 함수 호출 — 사이클마다 재구현·암산 절대 금지). 입력 = 가설별 OOS R 시계열, **누적 시도수 N**, 자기상관 차수, 실효표본 n_eff. **N의 기계적 정의 = (PROMOTED/REJECTED/TESTING 티켓 수) + (각 티켓이 param_grid에서 평가한 필터×출구 조합 총합) + (wfo 라운드 선택 +3) + (홀드아웃 조회 누적 H).** 채택 문턱은 **사이클 독립적으로 코드에 상수로 고정**(예: `R_min(N)=max(0.05, base_bar + k*log(N))`, `base_bar=0.05R`, `k=0.02` — 0.05R은 실효표본 ~700 클러스터 SE 채택금지선, RESEARCH 36행). **stats_gate.py·N 없이 PASS 선언은 무효.** **deflated Sharpe ≤ 0 또는 보정 후 p ≥ α/N 이면 단순 Sharpe·OOS가 양수여도 자동 REJECT.** 판정 근거는 모델 서술이 아니라 **stats_gate 반환값**뿐이다. **stats_gate.py 미구현 동안의 잠정 하드 문턱:** `OOS mean_r ≥ +0.10R AND 홀드아웃 mean_r > 0 AND raw OOS Sharpe ≥ 1.0`. 실효표본은 신호 수가 아니라 **중복 없는 거래일/주 블록 클러스터**로 추정(연구 이력: 신호 1만개라도 실효 ~700); 일/주 클러스터 부트스트랩 CI가 0을 포함하면 유의하지 않음; 실효 n<50이면 자동 REJECT. 게이트 공식을 루프 도중 바꾸는 것은 거짓 승리로 간주(INVALID).
7. **포트폴리오 생존:** `portfolio.py`로 4슬롯·쿨다운·연패축소 실거래 제약에서 자본배율>1 & 허용 MDD. 최종 현실성 판정은 신호단위 R이 아니라 portfolio 결과 우선.

## 6. 신규 가설 공간 — 마스터 백로그(고정) + 우선순위
────────────────────────────────────────────────────────

죽은 6군은 **금지**. 새 엣지는 "단순 14메이저 기술적 신호" **밖**에 있다(메타결론). 아래 **마스터 백로그(고정 10개)**를 우선순위로 둔다 — 각 항목은 정확히 1회 정식 시도가 의무이며, 위일수록 비용 문턱을 넘을 구조적 이유가 크고 구현 비용이 낮다. 선택 규칙: **(구조적 엣지 근거 강도 × 비용문턱 통과 가능성) ÷ (구현·데이터 비용)** 높은 순, 동률이면 상위 티어 우선.

- **티어 A — 비용·실행 구조(약엣지의 비용 문턱을 낮춤):** A1 메이커 전용+리베이트 실행 모델(지정가 미체결/부분체결·체결확률·큐를 study에 명시 구현 — §5-4 강제), A2 회전율 최소화/보유시간 연장, A3 비용 민감도 곡선(cost∈{0,maker,taker}로 "어느 비용에서 죽는가" 역산).
- **티어 B — 비가격/대체 데이터(가격 효율성 밖):** B1 베이시스/펀딩 term-structure(현물-선물 베이시스, 다음 펀딩 예측; funding_v2 확장), B2 청산 히트맵/OI 변화/롱숏 비율, B3 온체인·거래소 흐름 또는 F&G 극단 컨트라리안(aggregate 재사용). 각 B는 §3-6 as-of/lag를 먼저 원장에 적고 시작.
- **티어 C — 미시구조/실행 알파:** C1 세션별 단기 평균회귀/갭·오버나이트, C2 변동성 레짐 스위칭(레짐 게이트 임계는 train에서만 결정, 사후선택 금지).
- **티어 D — 메타·앙상블(과적합 위험 최고):** D1 메타라벨링(약신호에 거래여부 2차 분류 — 라벨 룩어헤드·CV 누수 극도 주의), D2 레짐별 전략 스위칭(시도 수 폭증 → §5-6 문턱 급상향).
- **티어 E — setup 밖(권고만, 자율 구현 불가):** 기관급 저지연·저비용, 비공개 대체데이터. 백로그가 E만 남으면 §7 STOP.

마스터 백로그(A1,A2,A3,B1,B2,B3,C1,C2,D1,D2)에 새 항목을 append하려면 ⓐ현 환경에서 즉시 데이터 확보 가능 + ⓑ죽은 6군 및 기존 10개와 5축 지문이 모두 다름을 원장에 입증해야 한다. 둘 중 하나라도 불충족이면 등재 불가(라벨만 새로운 무한증식 차단).

## 7. 한 사이클 = 다음 절차 (순서 고정, 자기 페이싱)
────────────────────────────────────────────────────────

(a) **부팅:** §1로 문서·원장·STATE 로드, 상태 복원. `last_status=STOPPED`+신규 OPEN 없음이면 즉시 종료.
(b) **가설 선택:** §6 우선순위로 **실행가능한 미시도** 가설 1개. 직전 3개 가설과 5축 중 3축 이상 같으면 **근접중복 자동 REJECT(재튜닝 금지)**. 백로그가 티어 E만 남으면 §8 STOP.
(c) **티켓 생성 + 사전등록:** §4 필드로 H-NNN OPEN 작성. 메커니즘·신규성·룩어헤드 위험·**성공 바/평가식**을 검증 시작 **전에** 기재.
(d) **구현/백테스트:** 가장 가까운 `research/` 골격 확장. study `signals` 스키마 보존. 평탄 노브면 param_grid 축약(§2).
(e) **룩어헤드 감사(§3):** 항목별 + 음성통제. 의심 → 즉시 REJECT/INVALID.
(f) **검증:** wfo.py로 OOS+동결 홀드아웃을 **maker·taker 양쪽** 실행, portfolio.py로 4슬롯 현실성, 비용민감도 곡선, (펀딩 관여 시) price_neutral 분해.
(g) **판정(§5):** stats_gate 반환값 기준. 전부 충족 → 다음 단계, 아니면 `REJECTED`+정직한 사유. `CONSECUTIVE_REJECTS` 갱신.
(h) **원장·커밋(§9):** 결과를 정직히 기록(음수도 그대로), 커밋. STATE.json 원자적 갱신.
(i) **승급(통과 시만, §8):** `status=AWAITING_FORWARD`로 표기 후 즉시 (b)로 복귀.
(j) **다음 사이클 또는 STOP.** 한 사이클이 다른 사이클의 가정을 깨면(새 룩어헤드 발견 등) 영향받은 과거 결과를 원장에서 정정 표기한다.

**무인 운전:** 사람 확인을 기다리지 않는다. 데이터 대량 다운로드 등으로 길어지면 `run_study.py --smoke`로 파이프라인을 먼저 검증한 뒤 풀런한다. 환경 제약(데이터 부재·API 한도)에 막히면 원장에 BLOCKED로 기록하고 다른 가설로 우회한다(멈추지 않되, BLOCKED 회계는 §8 참조). 비결정적/네트워크 단계는 재현 명령어를 남긴다. **루프 구동:** 각 사이클은 (a)~(j)를 완수하고 원장·STATE를 커밋한 뒤 종료한다. 다음 사이클은 외부 스케줄러(/loop 또는 cron)의 재주입으로 시작하며 **한 주입 = 한 사이클이 기본** — 한 턴에 여러 사이클을 강행해 컨텍스트를 소진하지 마라.

## 8. 전진 페이퍼 승급 + 정직한 STOP
────────────────────────────────────────────────────────

**전진 페이퍼는 본 연구 루프의 통제 밖 비동기 단계다.** 봇은 15분 GitHub Actions cron + paper_engine + learner의 Wilson 게이트로 돌며, 자율 루프가 샌드박스에서 스스로 발생시킬 수 없다(실시간 시세·경과·CI 필요). **백테스트 홀드아웃·OOS를 forward paper의 대체로 결코 간주하지 마라.** PROMOTE 가설은 `src/`를 건드리지 않고 `research/forward/<H-NNN>.json`에 `{promoted_at, signal_spec(파라미터·심볼·진입/청산·기간), min_observation_days: 30, min_signals: 50, cost: taker}`를 적고 `status=AWAITING_FORWARD`로 둔 뒤 즉시 (b)로 복귀한다. 후속 사이클은 `promoted_at` 이후 실시간 신호가 30일·50신호를 충족하기 전에는 절대 재평가·재튜닝하지 않는다. 승급 게이트는 `src/risk/learner.py`의 `wilson_interval` 기준(min_trades≥50 + 승률 Wilson 95% 하한 > 손익분기 28.6%). **forward 미완 가설은 AWAITING이지 확정 엣지가 아니며, forward 결과 미확인 상태에서 §8-2 확정 종료를 선언하지 않는다.** 실거래 전환은 자율 루프의 권한이 아니다 — forward 30일+ 양수라도 너는 증거·재현절차·잔존 리스크를 정리해 **"실거래 후보"로만 보고하고 사람 승인을 명시 요구**하며, `src/`의 실거래 토글·실주문 경로를 절대 수정·실행하지 않는다(이력 권고: 실거래 금지, 페이퍼 유지).

**정직한 STOP — '거짓 무한'이 아닌 '정직한 무한'. 다음 중 하나면 STOP하고 최종 보고한다(기계 판정):**
1. **백로그 소진:** §6 마스터 백로그 10개가 모두 `REJECTED|PROMOTED`이고, **실행가능(데이터 확보) 미시도 OPEN 항목 = 0**일 때만. (BLOCKED는 REJECT가 아니지만 진전도 아니므로 백로그 잔량 카운트에서 제외한다.) 또는 **연속 K=5 사이클 PROMOTE 0건이면서 신규 가설이 전부 BLOCKED 또는 죽은 6군 재포장**으로 판명되면 현 환경에서 실행가능한 새 각도 소진 신호로 보고 STOP. → "Bybit 메이저/중형 퍼프 + 페이퍼봇 비용구조에서 단순~중간 복잡도로 짜낼 엣지 없음. 남은 가능성은 이 setup 밖(기관급 저비용·저지연, 비가격 대체데이터, 시장조성/리베이트)"을 정직히 결론(WFO 142행 일치). 결론에 시도 목록·각 기각 사유·비용 분석·BLOCKED 목록(필요 데이터/인프라)을 첨부한다. BLOCKED 해소(데이터 파이프 구축)는 본 루프 범위 밖으로 명시 분리.
2. **엣지 후보 확정:** 한 가설이 룩어헤드0·WFO·동결홀드아웃·양방향비용·stats_gate·포트폴리오·**전진 페이퍼**까지 전부 통과 → 후보로 보고(실거래 전환은 여전히 권고하지 않음).

어느 경우든 **게이트를 완화/우회/재정의해 거짓 승리를 선언하지 않는다.**

## 9. 파일 소유권·브랜치·커밋 규율 (CLAUDE.md 준수)

- **쓰기 허용 화이트리스트:** 이 루프는 `research/`(코드·산출물·`research/ledger/`·`research/forward/`·`research/reports/`)에만 쓰기 가능하다. `src/`(strategy·exchange·data·risk·paper_trading·bot.py)·`config/`·`tests/`·`.github/`·`docs/`는 **읽기 전용 — 한 줄도 수정 금지**(소유 에이전트·Orchestrator만). 실거래 전환·main 병합·config 변경은 절대 수행하지 않는다.
